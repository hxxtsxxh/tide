## What ships

- `/` starts with New board for a fresh browser. Original title/question/URLs/requirements form, editable live example inputs, bounded real source discovery chooser, effective source-host list and provider disclosure.
- Typed same-origin research boundary in `src/lib/client/api.ts`: create, discover and refresh; bounded client wait; no implicit retry or fixture fallback. It rejects malformed/fixture responses rather than treating HTTP 200 alone as evidence.
- Sources → facts → decisions, literal passages, source hashes, observation/cache metadata, alternative support groups, transitive answer dependencies, local dependency review/correction notes, history and actual execution trace. Trace explicitly says refresh-all comparison is not measured.
- IndexedDB v1 library and active-board restore; one transaction compares expected local revision and saves board/history/active pointer. Full revisions are immutable and retained until delete. Cross-tab broadcasts exclude the sender. Stale writers fail without overwriting the saved board.
- Automatic save, Save locally retry for unsaved results, Reload saved, explicit export, bounded validated import, and delete confirmation with export first. Imports discard the snapshot and remain unverified, including snapshot:null archives. A live rebuild creates a new board and preserves the historical original.
- Archive validation checks size/schema, unsafe URLs, prototype keys, node bounds, duplicate IDs, dangling dependencies and cycles, including each imported historical revision. Source/user text renders as React text; no raw HTML rendering.
- Finite client-only Simulation Lab: capacity semantic change, failed source read, harmless formatting change. Visible SYNTHETIC FIXTURE and mode=fixture; no server/model/fetch operation.
- `/privacy` explains browser vs provider processing, retention/export/delete, quotas, sources and limits. `/integrations` explains project-scoped Claude Code/Codex setup, host permissions, file vault vs IndexedDB, explicit archive transfer and no polling.
- Required API.md test IDs and the prepared custom-board shotlist are retained. `run-request` targets a span inside the real create submit button; `sample-button` only fills editable inputs.
