# T04 handoff — domain engine, refresh planner, signed domain snapshots

## What exists (all inside T04-owned paths)
- `src/lib/domain/hash.ts` typed semantic hashes (number 7 != string "7"; only whitespace normalized), content hash, answer hash, stable IDs (`s_/f_/a_` + 8 hex from URL / fact key / dependency set).
- `domain/graph.ts` `buildGraph` (duplicate, dangling, self, cycle, >40 nodes) + deterministic topo order + O(V+E) `reverseClosure`.
- `domain/support.ts` DNF `evaluateSupport` -> supported | conflicting | unknown (failed/partial read) | missing | deleted. The board contract keeps 3 statuses (`boardFactStatus`); the richer state lives in the signed domain state.
- `domain/plan.ts` `planRefresh`: separate `affected` (logical closure), `needsRecompute`, `recompute` (attempted), `deferred`, `unknown`, `reused` (disjoint). `strategy:'baseline'` regenerates every computable answer from the same observations. `answerStatuses` never yields fresh for dirty/unknown/downstream answers.
- `domain/construct.ts` `constructBoard(board, meta, remap)`: stable IDs, same-key facts across sources merged into ONE fact with OR support sets, conflicting values -> `conflicting`, unverified quote -> `missing`. Also adopts pre-domain snapshots (remap=false keeps IDs).
- `domain/state.ts` `DomainState` (zod) carried inside the HMAC snapshot `meta.domain`: source contentVersion, fact semanticVersion/verifiedHash, answer hash/version/dirty/usesReq (null = unmapped), reqVersion, hash-chained `history` (last 20).
- `src/lib/server/snapshots.ts` `signState` / `openState` (HMAC+expiry, schema, graph + domain consistency, current source policy; all before quota).
- `src/lib/search/planner.ts` `createBoardDomain` (reuses `buildBoard` acquisition/verification, then constructs domain) and `refreshBoardDomain(req, state, deps, strategy)`.
- `src/app/api/_lib/specs.ts`: guarded specs for /api/boards and /api/boards/refresh; the two route files import them. `/api/discover` and legacy `/api/refresh` are unchanged.

## Behavior decisions
- A fact "changes" only when the typed hash of its verified value differs from `verifiedHash`. Body-only edits bump source `contentVersion` and cost one extraction, nothing downstream.
- Failed/partial/deleted/missing/conflicting evidence: the fact keeps its last value, answers -> `unknown`, nothing recomputed, nothing falsified. The same value returning later restores `fresh` with no model call.
- Requirement edits seed answers whose `usesReq !== false` (null/unmapped = conservative), are labelled `requirements_edit`, and make no Telem call.
- Affected-but-not-regenerated answers are `stale` and carry `dirty` so they are retried next refresh (spec prose says "unknown" at a deadline; stale is kept because the dependency change is known; never fresh).
- Revision summary records source-check cost separately from recomputation and what refresh-all would attempt (a planned number from the baseline planner over identical observations).
- Baseline: `refreshBoardDomain(..., 'baseline')` is real execution (tests show more answers sent to the model with identical Telem calls). Public board routes forbid `strategy` (API.md), so the paired baseline over HTTP stays the legacy `/api/refresh` (strategy=baseline) from T02 (`server/legacy.ts`).
