- Use the supplied Playwright MCP for actual browser inspection after a page exists. Do not substitute invented screenshots. Application fixture mode must be visibly labeled and unreachable as an implicit fallback in live mode.

## Required application shape
Use Next.js App Router + TypeScript in `src/`, a committed npm lockfile and Node >=22. The integrator may choose smaller dependencies if justified. Start with pinned versions from `.searchhack/tool-pins.json`; test installed versions rather than assuming compatibility. Implement `npm run dev`, `npm run start`, `npm run check`, `npm test`, `npm run build`, and `npm run evaluate -- --mode live --output artifacts/evaluation.json`. `check` must typecheck; tests must run once without watch. `start` must accept `--hostname 127.0.0.1 --port PORT`. `dev` also accepts that pair. Implement `/api/health` returning JSON {status:'ok', project:ripple, mode:'live'|'fixture'} with no secrets; it is a readiness endpoint, not proof of live integration.

App environment: TELEM_API_KEY, APP_MODEL_PROVIDER (`anthropic` or `openai`), APP_MODEL, and the selected ANTHROPIC_API_KEY or OPENAI_API_KEY. Get the checked model values from `.searchhack/local-models.json`; never hardcode an unverified model ID. Claude application API uses the verified API version in `.searchhack/toolchain.json`; use explicit bounded token and time limits. CLI subscription authentication is separate from app API billing. `.env.local` is available in this worktree for local app execution but its values must never enter prompts, output, client code or tests.

The evaluate script must honor SEARCHHACK_BASE_URL and --mode/--output, run bounded actual comparisons, and write {schemaVersion:1,project,mode,executedAt,caseCount,passed,failed,skipped,cases,metrics:{baselineStatus},limitations}. Baseline status is measured/observed only after actual paired execution; otherwise not_measured. Prefer adapting the supplied Python HTTP evaluator. Implement its baseline endpoint when applicable, using the same evidence/caps as specified. Live evaluation uses at least three meaningful supported cases; offline tests cover the full prepared fixture set. General fixture transport stays localhost-only with ALLOW_FIXTURE_MODE=true. Ripple alone may expose a finite, client-only, visibly labeled Simulation Lab. It must have no live-model, URL-fetching or arbitrary-fixture endpoint; it cannot masquerade as live evidence.

Before release, write root IMPLEMENTED-SCOPE.json with {project:ripple,scope:'full'|'compact'|'minimum'|'rescue',implemented:[specific capabilities],evaluation_case_ids:[prepared live case IDs],limitations:[omitted behavior]}. This is a statement about actual code, not the clock. Non-full releases must select explicit supported live cases (at most six) from the prepared evaluator. Full scope can leave case IDs empty for the default bounded sample. Tests must still cover meaningful success/conflict/unknown fixture behavior. Do not weaken the oracle or relabel an unsupported case passed. The final report records omitted coverage.

Default runtime is live. Every project must retain meaningful real Telem acquisition and page provenance. Bounded fixture mode is for repeatable evaluation and demo explanation, visibly labeled. Add request/body limits, fetch timeouts, safe URL validation, domain checks where specified, and a low public request budget to avoid unlimited judge-facing spend. No external database is required: use browser IndexedDB/local storage where the spec asks for persistence and serverless request-scoped processing elsewhere. Never depend on writable server disk for hosted persistence.
