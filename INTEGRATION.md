# Telem and direct Tavily integration

Telem remains Ripple's discovery/router. `/api/discover` performs a bounded Telem search and filters candidates through the operator's exact-host policy. Selecting a result creates a normal custom board. For supplied URLs, Telem reads those same pages for titles, status and destination qualification. Direct Tavily `POST https://api.tavily.com/extract` basic returns the actual `raw_content` used for source hashes, model fact extraction, literal quote checks and refresh observations. Reading one URL twice is not independent corroboration.

The server-only `src/lib/search/acquire.ts` is used by board creation, forced refresh and guarded legacy `/api/refresh`. The existing stdio MCP calls the same custom-board API. No input fields, user credentials, public extraction endpoint, worker or database were added. Operator `TAVILY_API_KEY` joins the existing server-only Telem/model/signing/Upstash configuration; never put it in a `NEXT_PUBLIC_` variable or consumer connector configuration. `/api/health.sponsors` contains configuration booleans and provider roles only, not a live-readiness certification.

## Admission and limits

The existing same-origin/body/schema/allowlist/HMAC/signed-visitor/kill-switch guards remain. Atomic shared Upstash operation quota is reserved before either provider call; Redis holds quota counters only. Both calls share the request's remaining 45-second deadline and cancellation. Telem can use its existing bounded transient retry; Tavily has one attempt with no automatic advanced/crawl/retry escalation. At most five selected URLs, basic depth, provider timeout 15 seconds, HTTP timeout 20 seconds, 1.5 MB wire cap and at most 30,000 raw characters per source. Ripple then retains the existing 12,000-character model-input cap per source (60,000 total). Truncation stays partial; facts in omitted content remain unknown. `query` and `chunks_per_source` are absent so content is not query-reranked.

Requested and returned Tavily URLs must satisfy the exact existing source policy and match each other. Unexpected result URLs are rejected. Telem's out-of-policy canonical destination or HTTP failure disqualifies a source even if Tavily returned content. Provider-side redirect chains cannot be fully audited. `observedAt` is the extraction-attempt observation time; neither upstream cache age nor publication time is established. Telem `no_cache` applies to Telem only, without a claimed Tavily cache bypass.

## Evidence and compatibility

All original BoardEnvelope fields/routes remain. Additive source fields are `extractor`, `provider_request_id` (observed or null), `extraction_status` and `extraction_error`. Quotes must occur in actual returned normalized text and fit in the preserved source excerpt before signing. Historical revisions remain distinct. Failed refreshes keep the old excerpt's extractor/request attribution; the new attempt stays in trace. If new text cannot be fact-extracted, `historical_unrevalidated` marks the retained old text. The evidence view shows source URL, extractor, status, batch usage and errors; unknown/partial evidence does not make answers fresh.

A direct trace row records `kind:fetch`, `provider:tavily`, `service:tavily`, `transport:direct`, `endpoint:extract`, `mode:live`, status, nullable upstream `requestId`, a separate local `callId`, nullable reported `usage`, `cache_state:unknown`, elapsed milliseconds, actual HTTP attempts and selected URLs. Telem rows keep the underlying provider and add `service:telem, transport:telem`. Batch attempts appear once, on the first Telem source row. Credits are recorded once per Tavily batch, not multiplied by URLs. Zero credits is an observed value, not a free-usage promise.

Empty HTTP-200 results, per-source failures, duplicate/foreign URLs, auth/rate/credit errors, oversized data and cancellation remain explicit. A bounded Telem-text fallback is labeled `extractor:telem, extraction_status:degraded_fallback`; it never counts as successful Tavily. A missing key likewise stays degraded, not fixture success. The strict legacy JSON schema retains its original fields: its trace notes report both services and HTTP accounting; its `fetches` list counts source pages and `cache_mode` describes Telem, while Tavily freshness remains unknown. Earlier page-count comparisons must not be presented as measurements of total provider work.

## Verification and release

`npm test` includes adapter and end-to-end fake-transport tests. `npm run test:tavily` runs that subset; tests prove Tavily-only quotations and changed content materially control facts and refresh, Telem qualification remains active, failures are explicit, attempts/credits are deduplicated and legacy compatibility is retained. `npm run test:mcp` retains subprocess protocol tests. `scripts/verify-vertical-slice.mjs` performs a bounded actual admitted create → user edit → source refresh flow. Current source observations are in `demo/TV01-verification.json`.

The controller alone publishes code. Keep existing independent HTTPS browser and MCP gates. TV02/controller runs the read-only external sponsor gate on the integrated deployment; local checks cannot set sponsors_ready or public_ready. Existing release reports were not rewritten. No native building-agent connector configuration was installed.
